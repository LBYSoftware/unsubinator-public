Unsubinator setup guide

← Back to Unsubinator

You'll create a free Google Cloud project so that Unsubinator can read your Gmail headers with your own permission. It costs nothing and needs no billing account. Allow about ten minutes.

The pictures are illustrations with example data (you@example.com and a made-up client ID). Google changes its screens from time to time, so yours may look a little different, but the names of the buttons and fields should match.

You'll need this item ID in step 7: mokkckihdecngaghbheeecogajbpaahc

1. Download and unzip

  1. Download unsubinator-selfinstall-v0.2.8.zip and unzip it. You'll get a folder called unsubinator with manifest.json inside it. Keep it somewhere permanent, because Chrome loads the extension from that folder.

2. Create your Google Cloud project

  1. Go to console.cloud.google.com/projectcreate and sign in. Type a project name (1) and click Create (2). Ignore any free trial offers.
  2. With the new project selected, open the Gmail API page and click Enable.

3. Set up the consent screen

  1. Open Google Auth Platform and click Get started. Enter an app name (for example "Unsubinator"), choose your email as the support email, choose External as the audience (1), add your email as the contact, tick the agreement and click Create.
  2. Go to Data access, click Add or remove scopes (1), paste https://www.googleapis.com/auth/gmail.readonly into the manual scopes box (2), then click Update and Save.
  3. Go to Audience, find Test users, click Add users (1) and add your own Gmail address. Only addresses on this list can sign in.

4. Create the OAuth client

  1. Go to Clients and click Create client. Choose Chrome extension as the application type (1), give it any name, and paste mokkckihdecngaghbheeecogajbpaahc into Item ID (2). Click Create.
  2. Copy the Client ID it shows (1). It ends in .apps.googleusercontent.com. You can find it again later on the Clients page.

5. Add your client ID and load the extension

  1. Open manifest.json in a plain-text editor (Notepad, VS Code, or TextEdit in plain-text mode). Replace YOUR_CLIENT_ID.apps.googleusercontent.com with your own client ID. Keep the straight quotation marks and the comma at the end of the line, then save.
  2. In Chrome, go to chrome://extensions. Switch on Developer mode (1), click Load unpacked (2) and choose the unsubinator folder, the one that directly contains manifest.json.
  3. Check that the ID on the extension's card is mokkckihdecngaghbheeecogajbpaahc (3). If it isn't, sign-in will fail with "bad client id".

6. Run your first scan

  1. Click the Unsubinator icon and start a scan. Google will say the app isn't verified. That's expected, because it's your own project and you're the developer. Click Advanced (1), then Go to Unsubinator (unsafe) (2), then Continue (3) to allow read-only access.
  2. A progress bar shows the scan as it runs, and the senders appear when it finishes.

If something goes wrong

  • "Manifest file is missing or unreadable": you picked the wrong folder, or the edit in step 9 broke the file (curly quotes or a missing comma). Pick the folder that directly contains manifest.json, or unzip a fresh copy and redo step 9 in a plain-text editor.
  • "Setup needed" in the popup: the client ID hasn't been added to manifest.json yet. Do step 9, then click the reload icon on the extension's card.
  • "bad client id": check the extension ID in step 11 and that the item ID in step 7 matches it. Changes to a client can take several minutes, occasionally longer, to start working.
  • "Access blocked" or a sign-in refusal: the Gmail address isn't on your test users list (step 6).

Good to know

  • While your project is in Testing mode, Google signs you out about every 7 days. Just scan again and approve.
  • Chrome may warn about developer-mode extensions each time it starts, and it won't update the extension automatically. Check this page for new versions.
  • To remove access at any time, click Disconnect in the extension or visit myaccount.google.com/permissions.
  • Your Gmail data only ever passes between your browser and Google. See the privacy policy.
